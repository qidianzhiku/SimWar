# MAIN IM-O2 Reality Join

## Goal

Extend the existing IM-O1 diagnostic seam into one exact, read-only Reality Join that combines the current diagnostic readiness with the already-owned M4 portability, M5 holdout, and M29 Shanghai support evidence. The feature must preserve the distinction between compatibility, eligibility, and official realized truth.

## Boundaries

- Use the existing ModelQualificationService, route family, role BFF, JSON authority, and UI surfaces.
- Add one versioned shared contract and one derived service projection; no new writer, store, registry, truth authority, or regional-transfer engine.
- Keep M4 as `PORTABILITY_EVIDENCE_WITH_LIMITS`, M5 as `NOT_ELIGIBLE`, M29 as `LOOKAHEAD_READY` with `formal_binding_eligible=false`, and Provider OFF.
- Teacher/Admin may see exact provenance and bounded limits. Student receives only role-safe readiness/evidence classes and limits.
- Any exact identity movement must return `REBASE_REQUIRED`; no implicit selectors.

## Sequence

1. Round 0 freeze: verify current source, support packs, route/OpenAPI seam, ownership, and clean isolated worktrees.
2. C1 contract/provability cell: add the shared Reality Join DTO and schema with contract tests.
3. C2 evidence-composition cell: add a pure support evidence composer and focused tests, importing only shared contracts and current support builders.
4. RED integrator: inspect and cherry-pick sealed cells, add the service projection and existing role route, update OpenAPI and role-safe UI, and add focused integration/browser coverage.
5. Run cell-targeted, integration, authority, typecheck, lint, hidden-Unicode, direct-store, build, bundle, and applicable browser gates.
6. Produce exact-head evidence, create one Product PR, and only merge if every required remote gate is fresh and green.
7. After merge, perform detached H3, write lineage/tombstone/handoff/cleanup evidence, and stop without starting IM-O3.

## Acceptance

- One Product PR only, no force push or history rewrite.
- No new formal writer/store/registry or official REALIZED mutation.
- Contract and OpenAPI parity, tenant/role-safe projections, exact support status preservation, and rebase behavior are machine-tested.
- Final archive includes delivery verification, current reality, tool and vault receipts, cell manifests, validation, merge/H3, lineage, cleanup, known limits, non-proofs, and SHA256 manifest.
