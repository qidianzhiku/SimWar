# MAIN-SH-FV-O1: Governed Shanghai Full-Vertical Candidate

## Scope

This plan executes the first ordered MAIN macro from the Shanghai mainline portfolio at the current `origin/master` anchor. The implementation is limited to a read-safe candidate-to-delivery binding seam and the already implemented read-only Teacher readiness route. It does not activate a Shanghai runtime, create a Shanghai registry/app/kernel, mutate official Truth/Settlement/ParameterSet state, enable AI/Provider/PostgreSQL runtime, or start N+1/N+2/N+3.

## Implementation sequence

1. Add a shared, pure identity-binding contract for the R7C candidate and its formal ScenarioPackage, ParameterSet, and PluginRelease references. The contract must compare tenant, course, scenario ID/version, parameter ID/version/seed, plugin IDs/versions, and candidate scenario-family/compiler metadata. It reports stable issues and explicitly labels content-digest verification as reference-only unless an authority artifact is supplied.
2. Add failing unit/integration tests for every mismatch class, for successful binding, for immutability/non-write markers, and for the Teacher-safe projection not exposing protected fields.
3. Wire the validator into `createCourseDeliveryBlueprintV1` as a required input. The blueprint records the validated identity evidence but remains a teaching/configuration candidate; it does not write or change formal authority state.
4. Reconcile the shared R7 Teacher selection package with the existing GET readiness route: mark the route as implemented read-only, keep commands/write flags false, preserve the no-go/non-proof list, and leave student visibility, settlement, replay, ParameterSet writes, and runtime activation forbidden.
5. Add the readiness GET operation and response/error shape to `contracts/openapi/p0-api.openapi.yaml` without changing route behavior.
6. Update only the directly related architecture/quality/operations evidence docs to state the current read-only route and its limits.
7. Run focused tests first, then `npm run typecheck`, `npm run lint`, `npm run test:contract`, and `npm run build`. Run the full suite once if time permits and report the inherited snapshot timeouts separately.
8. Produce a clean evidence ZIP outside the repository containing the source anchor, changed-file manifest, test receipts, explicit non-proofs, and SHA-256 manifest. No private local source roots or real project data are ingested.

## Acceptance criteria

- A mismatched candidate/formal reference is rejected before a course-delivery blueprint is returned.
- A matching candidate produces a binding evidence object with `formal_truth_write: false`, `settlement_write: false`, `parameter_set_write: false`, `runtime_activation: false`, and reference-only digest status.
- The readiness route is represented consistently in shared contract, OpenAPI, implementation, tests, and docs as read-only Teacher projection.
- Student-safe and truth-protection tests remain green.
- No settlement, replay hash, canonical decision, database schema, or runtime adapter semantics change.
- Full completion is not claimed if required tests or external review gates remain unverified.
